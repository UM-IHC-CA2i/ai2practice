Step 1 · The question

The question

How many CT scans were done last month, and of which body regions?

A radiology department asks questions like this every month. The answers decide how scanner time is booked, how many technologists are on each shift, and whether a rise in head CTs from the emergency department needs a closer look. The answer sits in a table that the scheduling system can export: one row for each study, with the date, the body part scanned, the patient's age and the department that ordered it.

You could open that table in a spreadsheet and count by hand. In research you do it with code instead, because code can be rerun next month in seconds, gives the same answer every time, and shows a reader exactly what you did. In this lab you write that code in Python, the programming language most used in data science and AI research. You run it in Google Colab, a free website that runs Python on Google's computers, so there is nothing to install. Colab works with notebooks: documents that mix short explanations with cells of code you run one at a time, each showing its result underneath. You save the finished notebook to GitHub, a website that stores code along with every earlier version of it.

Your table is one month of CT studies, 300 to 500 rows, with the columns study_id, date, body_region, age and ordering_dept. It is made up, not real patients, and it is generated from your GitHub username, so your numbers differ from everyone else's. That is how step 5 can check that the answers are really yours.

By the end of this lab you can:

  • Run a notebook in Colab and use variables, lists, loops and simple functions in Python.
  • Load a table with the pandas library and count how often each value appears.
  • Draw a labeled bar chart that someone else can read.
  • Save your notebook to your own GitHub repository and start toolkit.py, the file of your own functions that later labs reuse.

Step 2 · The idea

Counting is the first analysis

Almost every clinical dataset you meet in research is a table. Each row is one thing you counted, such as a study or a patient, and each column is one fact about it. In Python, tables are handled by pandas, a library: a bundle of ready-made code that you load with one line instead of writing it yourself. pandas holds a table in an object called a DataFrame, and gives you tools to filter, count and summarize it.

The first thing to do with almost any table is count: how many rows share each value of a column. Before letting code do it, count a small batch by hand, the way you would with a printout and a pencil.

Interactive: count by hand, then with code

Twenty-four CT studies from one morning (practice data, not your dataset). Click each study to add it to the bar for its body region. When you have the idea, let the code finish the job.

The output under the button is what one line of pandas, value_counts(), prints for this column. On your full month it gives the answer to the lab's question in less than a second, and it will give the same answer next month on next month's table. Turning those counts into the bar chart above takes one more line, using a plotting library called matplotlib. A chart is part of the answer, not decoration: a reader should understand it from its title and axis labels alone, which is why Part 3 asks you to label yours.

Step 3 · Warm-up

Warm-up: read the code

Two short reading checks. They are not graded and always show the explanation. They also work as a skip test: they cover what the notebook's first parts teach.

What does this code print?

regions = ["Head", "Chest", "Chest", "Spine"]
count = 0
for r in regions:
    if r == "Chest":
        count = count + 1
print(count)

A for loop visits each item of the list in turn and calls it r. The if line adds 1 to count only when r equals "Chest", which happens twice. Note the two kinds of equals sign: = stores a value in a name, while == asks whether two things are equal.

Warm-up: put it in order

Drag the four lines into the order that loads the table, counts the body regions and draws the chart. On a keyboard, focus a line and use the arrow keys.

  1. counts = df["body_region"].value_counts()
  2. import pandas as pd
  3. counts.plot(kind="bar")
  4. df = pd.read_csv("ct_log.csv")

Python runs code from top to bottom, so each line can only use what earlier lines made. The library has to be loaded (import) before you use it, the table has to be read before you can count it, and the counts have to exist before you can plot them. pd is the usual short name for pandas, and df the usual name for a DataFrame.

How you'll code in this lab

What the coding modes mean

Every task in the notebook is tagged with one mode. In Write tasks you write a few lines yourself from an empty cell, with a hint and a hidden solution. In Fill in tasks most of the code is there and you complete the blanks. Reuse tasks import a function you wrote in an earlier lab from your own toolkit.py, the way real projects grow. In Direct the AI tasks you ask an AI assistant (Colab's built-in one is suggested, but any is fine) to write the code, paste it in, run the test cell, and note in the AI-use log what you asked and what you had to change. Fix tasks give you code "written by an AI" with one realistic mistake to find. Read tasks ask you to put lines in order or predict what code will print before you run it.

Early labs lean on writing code yourself, because that is how the basics stick. Later labs lean on reusing your code, directing an AI and checking its work, because that is how research code is written now, and checking is the part a person must still do.

Save your work to GitHub

Colab runs the notebook, but it does not keep your work for you. You keep it in your own copy of the course repository on GitHub (a repository, or repo, is a project folder on GitHub with the full history of every saved change). The first time, you make that copy, called a fork; after that, you save into it whenever you finish a part.

  1. First time only: sign in to GitHub (create a free account at github.com/join if you need one), open the course repository, click Fork, then Create fork. Your copy lives at github.com/your-username/CA2i-Research-Launchpad.
  2. When you finish a part, choose File > Save a copy in GitHub in Colab. The first time, Colab asks for permission to use your GitHub account; allow it.
  3. Pick your fork, your-username/CA2i-Research-Launchpad, branch main, and keep the file path lesson-notebooks/Lab_1_Python_Colab_GitHub.ipynb. Write a short note about what changed (for example "Part 2 done") and click OK.
  4. Next time, open the notebook from your fork (in Colab: File > Open notebook, then the GitHub tab) so you carry on from where you stopped.
